# 强符号与弱符号

## 定义
强符号与弱符号是链接器处理多重定义时的分类规则：**强符号**指已初始化的全局变量和函数定义，**弱符号**指未初始化的全局变量。当多个 .o 文件中有重名符号时，链接器遵循三条规则——只有一个强符号则用它；多个强符号则报「重定义」错误；全是弱符号则任选其一（潜在 bug）。

## 公式

| 代码 | 符号类型 | 原因 |
|------|----------|------|
| `int a = 5;` | 强符号 | 已初始化的全局变量 |
| `int b;` | 弱符号 | 未初始化的全局变量 |
| `void f() {}` | 强符号 | 函数定义 |
| `static int c;` | 局部符号 | static 修饰，不参与强弱判断 |

## 通俗理解
> 强符号和弱符号就像公司里的「正职」和「临时工」：`int a = 5;` 是正式员工（强符号），占了一个确定的编制；`int b;` 是没有分配岗位的临时工（弱符号），可以被更强的定义覆盖。如果两个部门各自任命了一个「部门经理」（两个强符号重名）——链接器直接报冲突，因为一个职位不能有两个正式任命；但如果都是临时负责人（全是弱符号），则随便选一个，可能导致混乱。

## 🔗 关联

- 符号类型 — 强弱符号是全局符号的进一步细分
- 符号解析 — 链接器依据强弱规则解决多重定义冲突
- ELF符号表结构 — 符号表的 bind 字段区分强弱绑定
