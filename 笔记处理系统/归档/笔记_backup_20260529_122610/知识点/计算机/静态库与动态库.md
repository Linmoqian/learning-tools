# 静态库与动态库


## 定义
静态库（`.a` / `.lib`）在编译链接时将库代码直接复制到可执行文件中，程序独立运行但体积大。动态库（`.so` / `.dll`）在运行时由操作系统加载器动态链接，多个程序可共享同一份库代码以节省内存，且更新库文件无需重新编译程序。两者的本质区别在于链接时机：编译时 vs 运行时。

## 公式

| | 静态链接 | 动态链接 |
|------|----------|----------|
| 文件格式 | `.a` (Linux) / `.lib` (Windows) | `.so` (Linux) / `.dll` (Windows) |
| 链接时机 | **编译时**嵌入 | **运行时**加载 |
| 可执行文件 | 大（包含库代码） | 小（只记录引用） |
| 内存占用 | 每个程序各自一份 | 多程序共享一份 |
| 更新方式 | 需重新编译链接 | 替换 .so/.dll 即可 |

## 通俗理解
> 静态链接就像「自带干粮去郊游」——把所有吃的喝的都打包进背包里，到哪都不求人，但背包沉得要命；动态链接就像「去美食广场」——只带个钱包（引用信息），到了地方共享厨房随时取用，轻装上阵。更新菜单也方便：后厨换道菜（更新 .dll），食客无需重新出门。代价是：如果美食广场没开门（找不到 .dll），程序就直接报错退出了。

## 🔗 关联

- 符号解析 — 静态链接和动态链接都需要解析符号引用
- 可执行文件 — 链接的最终产物
- ELF文件格式 — Linux 下静态库和动态库都是 ELF 格式的变体
